# 外贸助手 · 获客 / 交易双工作空间

完整的静态前端演示，基于已确认的双空间视觉方向重构。顶部从“发布”改为“获客”；内容发布仍是获客空间中的单一业务栏目。

## 查看

直接打开 `index.html`，或在当前目录执行 `python -m http.server 8080` 后访问 `http://localhost:8080`。无生产依赖，不需要构建或模型密钥。

## 页面结构

- 首页：只选择获客或交易空间。
- 获客：市场分析、产品分析、内容设计、内容发布。
- 交易：客户管理、聊天、报价系统、订单系统。
- 业务页：左侧栏目导航，中间单一工作面板，右侧栏目 Agent 对话。小屏把 Agent 放入可展开抽屉。
- 聊天：保留交易栏目导航，左侧会话列表（客服 Agent / 单人 / 群聊），右侧大聊天区；没有右侧 Agent 栏。小屏在会话列表与聊天内容之间切换。

## 已实现的前端交互

市场方向编辑和交接；多产品分析与人工事实编辑；英文演示内容生成、修改、版本管理；当前版人工审批和 Facebook 链接登记；客户新增、编辑、搜索、标签与跟进；会话筛选、单人及群聊本地消息、客服摘要交接；程序报价、版本失效、交期审批、同版确认和防重复建单；订单生产、平台外收款记录、发货与完成；附件名称记录；操作审计及带版本检查的撤销。

右侧“可编辑”允许受控演示指令修改当前对象，“仅建议”会先生成待确认修改。需要人工核实的价格、认证、发布、订单、收款和发货不因模式切换而自动执行。

所有修改与消息存于当前浏览器 localStorage。不是服务端持久化，不在访客间同步。支持设置中重置，存储不可用时回退到当前会话并提示。

## 能力边界

Agent 使用有限的前端规则处理示例指令，并非真实大模型。自由文本若无法匹配，会明确提示，不伪装为执行成功。Agent 间传递的是可查看的本地消息记录，不是真实多进程 Agent 通信。

附件只记录文件名、大小限制和所属页面，不读取正文，不上传，不解析 PDF，也不声称分析来自附件。聊天不连接真实客户、WhatsApp 或其他渠道；外部聊天输入只保存为本地演示消息。客服同步仅作用于关联的预置 KL Build Supply 示例资料，不把其摘要写给其他客户。

发布审批与引用产品版本绑定，内容或产品版本变更会失效。最终仍由人手动发布，链接登记未经平台核验。收款与物流只是人工模拟记录，不经手资金或核验真实履约。

## 文件

- `data.js`：种子数据与本地存储读取。
- `views.js`：页面布局、各业务面板、Agent 侧栏和独立聊天界面。
- `app.js`：路由、受控动作、审批状态、表单、交接和撤销。
- `styles.css`：统一视觉变量、双空间切换、响应式与减少动效。
- `verify.cjs`：可选浏览器回归，使用已有 Playwright，生产页面不依赖它。

## 验证

在可用 Playwright 环境运行 `node verify.cjs`。可设置 `PLAYWRIGHT_MODULE` 指定已安装模块路径，`BROWSER_BINARY` 指定浏览器，`QA_OUTPUT` 指定内部 QA 截图目录。回归检查真实前端状态变更、审批失效、版本冲突与布局；不代表任何模型或第三方连接器通过验证。
